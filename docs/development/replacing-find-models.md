# Replacing discovery models

The three enlarged bottles and the three appearances of one Rock are **replaceable trial art**. The user expects to supply better models. `110` removes cans/bricks and adds 60% collection exposure and physical release. Integration approval is not final art or style acceptance (`09`/`105`). Use existing gameplay and stable IDs when replacing visuals.

## Replace an existing model

`115` adds per-item `throw_speed` (metres/second) to both source catalogs: 8 for bottles, 4 for Rock. Sync writes `FindPhysics.throwSpeed` into the stable prefabs. Preserve or deliberately retune it with a replacement; test physical lift, wall contact, drop/throw and a checkpoint while held. `116` separates carry tracking from throw strength; replacements must also pass sustained jetpack/pitch changes and rest/wake checks with their new hulls. 136 removes the recognition timer: held/fresh input immediately collects eligible aimed items, independently of shovel cooldown. Replacement meshes must preserve exposure and direct-visibility checks.

The numbered steps below describe the bottle source root; use the linked rock guide for its isolated root and three-appearance batch. The Blender scripts author the original trial candidates. A supplied replacement uses its own retained source/export plus the catalog and sync command; do not run the old modelling recipe over it.

1. Record the supplied specific asset batch, license/source and applicable user authorization in the ledger. Retain its `.blend` source when Blender-authored and exports in an isolated source subfolder, such as `art/starter-finds/replacements/<batch>/`. Preserve its original license and update the source root `LICENSE.txt` with the active batch's rights/notices; sync copies that file into Unity. Never assume a replacement inherits the original model license or overwrite user-supplied originals.
2. Keep the item's **`content_id` unchanged**. Update its `fbx`, `collision_fbx` and texture paths in `catalog.json`; a new source filename is fine. Paths are relative to `art/starter-finds/`. One atlas group uses one consistent BaseColor/Normal/Masks set; change `atlas_group` if it needs separate materials. Remove retired generated groups only after checking all remaining references.
3. Supply one triangulated mesh and one material per entry, real metre dimensions, UV0 and tangent normals. The importer expects width/depth/height in `dimensions_m` and exports with +Y up. It bakes transforms and centres the mesh; never compensate with old scene/prefab scale. Supply a matching convex collision FBX with at most 112 distinct points / 220 triangles, matching outer dimensions and pivot. The retained `create_bottle_colliders.py` builds/validates hulls for the original Blender source. Sync attaches bottle physics to that hull; inspect fit and cooking warnings after replacements. A new category requiring fixed/compound collision needs an explicit contract/setup change.
4. Update the catalog dimensions if the actual object changes size. Source masks are **R metallic, G AO, B roughness**; sync creates Unity **R metallic, G AO, A smoothness = 1−roughness**. Base color uses sRGB; normal/masks are linear. Current maps cap at 2048 px with mipmaps and Windows BC7/BC5 compression.
5. Through the official Unity CLI, open saved MainGame outside Play Mode and run **Tools → Something Down There → Sync Starter Find Models**. It preserves retained `.meta`/prefab/mesh/catalog GUIDs, regenerates centred visual geometry and separate hull/256 exterior samples, enables convex prebaking and saves MainGame. Retired generated assets/metas are deleted from its five owned subfolders; keep user originals outside them. Run sync even for texture-only changes; generated edits are overwritten.
6. Verify ordinary light/partial soil exposure, oblique silhouettes, weak/strong digging, full bag/sale, attachment versus 60% pickup, falling/rest, further digging and reset. Load pre-change and released-pose saves; confirm identity, absence, pose and carried values. Run relevant catalog/physics/discovery/save tests and provide a current Windows build. Model dimensions affect support, hull fit and reveal readability, not only appearance.

The importer rejects mismatched dimensions, missing files, conflicting atlas maps, unsupported material/mesh counts and models exceeding the existing 0.5 m clearance envelope. A rejection calls for fixing source/specs or a deliberate placement change, not secretly resizing the item or generating a fallback shape.

## Change gameplay or retire an item

- **Visual replacement:** retain content ID, values/counts/rules and saved identities. Update source references, measured dimensions if necessary, preview/validation evidence, ledger and the active task result. Mark whether the new art is another trial or accepted final art; do not freeze it as final by default.
- **Name/value/count/size/category change:** edit the catalog plus starter contract, and the relevant numbered task. Existing saves retain historical values and population; changes apply to new finds/new games unless an explicit migration is selected. Update roster `40`, design `89`, final-content `09`, style `105`/presentation `57` only where their actual decisions or acceptance change. Do not rewrite completion records into transcripts.
- **New distinct item:** allocate a new content ID. **Retirement:** keep an old-ID mapping to compatible content and test it; never recycle an ID for an unrelated discovery. Legacy GUID mappings are compatibility rules, not obsolete art references to remove. Unknown IDs block loading rather than rerolling the world.
- Current migration maps original primitive GUIDs and retired can/brick IDs directly to bottles. It preserves old 96/72 populations, historical inventory/values and collected absence, normalizes mapped scales and changes only uncollected names. Migration works on copies and is idempotent. v1/v2 readers remain supported; v3 additionally saves released state/current pose. Release resumes from rest; motion itself dirties autosave.

## Remove or roll back this batch

Prefer a catalog-based visual swap that keeps IDs and compatible saves. To remove integration completely, restore the original three `Content/Finds/` references through the Editor, clear the catalog and restore 96/development gating; revert scoped builder/field/find/catalog/physics and related tests, then remove the owned StarterFinds folder/metas and setup and rebuild. Preserve v3 reading/migration for existing saves unless a tested downgrade is supplied; do not blindly revert the codec. See the ledger for TerrainVolume/Persistence shared hunks and physics files. Preserve legacy prefabs, user terrain, `Assets/_Recovery/`, sources and every save. Removed can/brick art is not a rollback target without a new request.
