# Task 151 - Evaluate an optional excavation timelapse

Type: design/research. Status: `planned`, deferred optional polish. Prerequisites: `148`, a worthwhile full run in `37`; no release dependency.

Feature: [optional systems](../../features/backlog/optional-systems.md). Context: [feedback](../../research/excavation-distinctiveness.md). The saved hole is already the player's lasting work; a recap must add enough value to justify capture/storage cost.

## Decision artifact and questions

- Compare no recap, a bounded sequence of occasional images, and a full deformation replay. Start with a proposed 30–60-second image interval and explicit storage cap, not full replay technology.
- Show camera/framing and underground visibility options, when the player sees the recap, skip/dismiss behaviour, retention/deletion, interrupted saves and Continue. No compulsory camera takeover during digging or terrain completion meter.
- Estimate frame/memory/disk impact using current save/render ownership and `63`; do not restart `80` qualification. Distinguish an eventual in-game player feature from repository review screenshots, which remain temporary under AGENTS.md.
- Present concrete sequences/costs and ask whether the memory/share benefit earns inclusion. No capture service, footage publication or automatic permanent gallery is authorized.

Done when include/defer/omit and rationale are recorded in the optional feature. Only an included, bounded design gets the next numbered implementation ticket and a player-reviewed Windows test; document completion is not an implemented replay.
