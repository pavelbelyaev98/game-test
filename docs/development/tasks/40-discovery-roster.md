## Task contract

- This is an explicitly scoped content-design task: define the roughly 20–30 ordinary and 30–50 distinctive types already targeted by the idea. Count `09` content once; mark `36` passive rewards and the `52` final reveal separately so their counts/ownership cannot duplicate ordinary content.
- Give each entry a stable content ID, recognizable shape, broad size, ordinary/distinctive role, related cluster, overlapping depth tendency, rough value band and early/middle/late novelty purpose. Plan sensible orientations and eligibility; no strict chronological spawn gates.
- Allocate concrete named batches to `41`–`44`, with sources or Blender briefs and an independently reversible integration boundary. Asset briefs are not import approval. Use the existing asset ledger only once a specific addition is approved.
- Research: read [progression/discovery findings](../../research/player-review-findings.md#progression-and-discovery), inspect starter recognition and the accepted `57`/`58` briefs, compare named content/cluster options and source feasibility, then prepare the roster proposal.
- Review with the user: ask which object themes/humour boundaries fit the setting, and review the proposed named roster/batches. Resolve unusually large finds with the user before including them; extraction is not silently added. Reserve the exact final-object decision for design task `61`, then implementation `52`.
- Acceptance: the reviewed roster covers the existing count targets without duplicate identities/roles, supplies believable-to-strange progression and lateral clusters, and gives every implementation batch a concrete checklist. Do not mark models or gameplay complete from this planning result.
