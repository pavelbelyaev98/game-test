# Task 97 - Design deliberate special discoveries and treasure chests

Type: design/research; documentation only. Status: `planned`. Prerequisites: baseline `101`; coordinate `96`'s physical categories if selected. Complete before `40` finalizes distinctive content; ordinary starter design `89` remains independent.

Features: [collection](../../features/backlog/discovery-collection.md), [content](../../features/backlog/discovery-content.md). Context: [idea assessment](../../research/player-idea-assessment.md). Delivery is a new numbered implementation task only after selection; `83` still owns optional inspection text, not this interaction system.

## Proposal to prepare

- Compare existing held pickup with a deliberate **bound Interact action, E by default**, for distinctive objects. Ordinary finds keep LMB. Show what sustained/toggled digging does when a special becomes collectible; it must neither auto-collect the special nor demand release on every ordinary item. Define priority over stations, prompts, repeat presses, pause/focus and rebinding.
- Produce a behavior/reward matrix with examples: ordinary sale item; distinctive sellable memory; optional useful object; protected passive reward; treasure chest; large anchored find. Examples are illustrative, not asset/roster approval. Distinguish size, rarity and interaction category; not every physically large object is a unique or buff.
- For each category, state recognition, action, destination/capacity, sale availability, purpose, persistence/rescue policy and first-discovery photo. Preserve the established `62`/`36` optional passives and `61` ending ownership; do not allow selling required protected state or quietly grant ordinary objects a new rescue exemption.
- Prepare a short chest opening sequence: required exposure, E to open, reveal, reward transfer and later empty state. Compare direct rewards with individually collectible contents; solve full inventory, moving/blocked lids, saving during opening, interruption and repeat visits. Select when reward identity/content is fixed so reload does not reroll it or duplicate value.
- Give chest contents a meaningful authored reward rationale and count them in `40`/`45`'s finite budget. No paid random rolls, separate key-search loop, repeated long opening animation or container whose reward cannot justify the interaction. One or two illustrative ordinary/strange chest briefs are enough to review the mechanic.
- Show a clearly documented sale/use outcome before an irreversible choice. A distinctive object may justify itself through humor, context and the personal display; recommend against requiring a functional power or quest for every unique.

## Questions for review

Review E-for-specials versus the current held flow, which categories need deliberate acknowledgment, chest reward transfer, and whether any proposed use-versus-sale choice is actually enjoyable. Select concrete examples and their outcomes rather than an undefined promise that every unique will be useful.

## Acceptance

The feature owns a reviewed input/state/reward matrix with full-bag, duplicate, reload, rescue and snapshot cases. Update affected control, content, display and passive tasks only for selected changes; preserve the old baseline until delivery. Create a bounded implementation task and required tracking handoffs before content batches; any proposed audio/model still needs specific approval. Rejection/defer is valid and must retain its reason.
