# Task 70 - Research return navigation and revisit aids

Type: design/research; documentation only. Status: `planned`. Prerequisites: `15`, `65`. Run the first comparison immediately after the production trip; paid `47`/`49` tiers supply later confirmation, not an entry gate.

Feature: [return and rescue](../../features/backlog/return-rescue.md). [Research](../../research/player-review-findings.md#scope-boundaries-and-conditional-investigation). [Queue](../tasks.md).

## Why and scope

HOME bearing is already conditional. The new marker suggestion addresses remembering a particular formation or branch, which differs from finding the surface or enduring a long commute. Resolve whether either aid is needed using the actual excavation; implementation is not pre-approved.

## Research and proposal

- Read `15` trip evidence and compare no aid, a coarse HOME bearing, and 3-5 reusable differentiated markers in representative lateral branches and multilevel excavations. Use a concrete annotated interaction prototype/decision artifact first; playable prototypes require an approved presentation scope. Record wrong turns, branch recognition, time to surface and time to revisit a remembered wall; later repeat with paid movement/detector tiers.
- Compare better route/material readability and adequate lighting first. A player enjoying their shaft or chambers is not a navigation failure.
- Consume `100`/`101`'s user evidence when available and pass any demonstrated known-route tedium to `99`, which owns movement/teleporter comparisons. Keep orientation, forgotten branches, empty surface walking and dull underground retracing separate; a HOME arrow cannot solve an already obvious but boring path. The user's horizontal-travel criticism concerned Meltopia, not a confirmed failure in this project.
- The [Meltopia report](../../research/meltopia-lessons.md) warrants an early concrete comparison rather than waiting until the endgame. Separate lost orientation from an obvious but tedious commute; report both without assuming HOME solves travel time. Test recognizable marker shape/label as well as color, placement/removal, clutter, reload and removed supporting soil. Marker count and free-versus-purchased access remain proposals.
- If justified, propose coarse HOME bearing for surface orientation and/or a simple player-placed marker for revisits. Neither gives an exact path, treasure coordinates, automatic waypoints or teleporting.
- For a marker proposal, specify placement/removal, count/clutter limit, cost or reusable ownership, visibility without seeing through walls, saving, and behaviour when supporting soil is removed. A flag/light example is not selected art or a climbable prop.
- Recommend keep absent, defer with a specific test trigger, or implement each candidate. Explain evidence and complexity; a decision to leave both absent is a valid outcome.

## Questions to resolve with the user

- Does the recorded problem warrant an aid, or is remembering/shaping the excavation part of the intended enjoyment?
- If needed, rough HOME direction, player-placed revisit markers, or both for distinct demonstrated problems?
- For a selected marker: what physical form, placement key, quantity/reuse and visibility feel useful without clutter or a building menu?

## Done when

Record each candidate's decision, why, excluded behaviour and evidence/revisit trigger in the feature. Only a selected aid gets a new numbered implementation task and an approved asset process; insert it before dependent full-run/release checks. `59`/`37` consume these decisions instead of treating research as a delivered mechanic.
