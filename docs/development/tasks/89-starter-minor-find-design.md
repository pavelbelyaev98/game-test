# Task 89 - Design the first real minor finds

Type: design/research; documentation only. Status: `ready`. User-selected next task. Prerequisites: existing collection/save behavior (`35`, `72`, `86`, complete); independent of paused lighting/equipment design.

Feature: [discovery content](../../features/backlog/discovery-content.md). Preserve [collection rules](../../features/backlog/discovery-collection.md). Research: [progression and discovery](../../research/player-review-findings.md#progression-and-discovery). Delivery: [09](09-starter-discoveries.md); later roster: [40](40-discovery-roster.md).

## Scope

- Design the first production batch of minor/ordinary finds to replace the current development forms. Prepare a concrete named roster for review before asking the user to choose individual objects.
- Specify the exact number of distinct item types, any variants, the total placed population and per-type quantities for this first batch. Distinguish types from repeated instances; the current 96-object field and full-game 20–30 ordinary-type target do not automatically determine this batch's count.
- Give each item a stable content ID, display name, dimensions, silhouette, materials/colors and identifying details, size/slot classification, initial sale value, detector eligibility with a physical rationale, placement/orientation/clearance and burial/depth tendencies. State partial-exposure recognition requirements and any exception needing review.
- Preserve held pickup, current 40% exposure plus actual visibility/range, ordinary inventory/sale behavior and durable identities. Describe compatibility when replacing development content in existing saves; do not silently reset or duplicate finds.
- Prepare feasible Blender or free commercial-use source briefs and references. Item selection is design approval only; specific assets, files, previews/licenses and removal plans still require approval before creation/import.
- This task owns the starter item selection formerly bundled into `57`. Presentation `57` consumes the accepted set; `40` counts it once and plans the remaining full-game roster. Large/distinctive finds, passive rewards and the final object remain with their existing tasks.

## Acceptance and review

- The owning feature contains one reviewed item table with exact counts and complete per-item specifications, a coherent visual/theme rationale, replacement/save plan and an explicit handoff to `09`.
- Resolve the batch theme, exact item set/counts and significant specification choices with the user using the concrete proposal. Record selected versus deferred options; numerical estimates remain clearly labeled until tested.
- Update `09`, `57` and `40` to consume the accepted selection. Do not claim assets or gameplay implemented from the design, and do not start production merely to illustrate a proposal.
