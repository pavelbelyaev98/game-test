# Task 150 - Integrate a selected uncanny variant batch

Type: implementation. Status: `planned`; inclusion undecided. Prerequisites: `149`, corresponding `40` roster entries and approved base-find content. `148` findings inform the experiment before wider rollout.

Feature: [discovery content](../../features/backlog/discovery-content.md). Generation owner: `45`; display owner: `51`. [Measurement hypotheses](../../research/excavation-distinctiveness-validation.md).

## Scope and research

- Deliver only `149`'s selected named pairs, stable identity scheme, copy/frequency policy and reward/record behaviour. Start with its bounded experiment, not a variant for every find.
- Inspect catalog, population serialization, detector filters and first-record identity. Use selected seeded generation with explicit finite population/value budgets; source/import changes cannot reroll existing saves.
- Prepare the exact Blender or commercially licensed asset batch with preview/license/files/removal, obtain approval, then integrate into MainGame. A tint/price change alone cannot satisfy an unmistakable authored surprise.

## Acceptance and questions

- Actual uncovering distinguishes each base/variant while preserving current exposure and input. Collect, sell/retain, photograph if selected, rescue and reload without duplication or changed historical prices.
- Validate authored occurrence across representative seeds, common-detector silence, ordinary/variant identity and old-save compatibility. `45` retains placement/cluster ownership.
- Observe whether players mention the strange discovery unprompted and whether it improves recall without constant joke fatigue; record actual exposure to the variants, not just a percentage average.
- Focused checks, CLI inspection and Windows build pass; update `40`/`45`/`51` only where selected rules require it. Return changed identity/theme/reward choices to `149` rather than deciding them while importing. Retire if `149` omits the system.
