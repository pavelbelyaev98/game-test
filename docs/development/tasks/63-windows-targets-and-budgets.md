## Evidence and tradeoffs

- Official CLI read-only inspection on 2026-09-09: Unity `6000.6.0f1`, clean `MainGame.unity`, Mono x64, automatic graphics APIs (DX12/DX11), Ultra quality with URP `17.6.0`, vsync 1, no explicit frame cap; URP asset uses render scale 1 and 4× MSAA. Window defaults 1920×1080, bordered/resizable; `DesktopWindow` fits startup to 75% of desktop bounds. No fullscreen selector or performance presets exist. Evidence: `unity/Logs/Task63/configuration.json`; native Task 35 log independently confirms Mono/DX12.
- Current reference machine: Windows 11 build 26200, Ryzen 7 9700X (8 cores/16 threads), RX 9060 XT (16 GB), nominal 64 GB RAM (Unity reports 63,033 MB), Samsung 990 PRO NVMe. This exceeds the baseline test candidates; reducing resolution here cannot certify slower CPU/RAM/storage. The latest build report confirms success at `2026-09-08 19:23:51 UTC`, about 210 MB; build duration/size are not launch time or resident memory.
- Task 34's local Editor profile (`unity/Logs/Task34/performance-result.json` / `profile-final.cs`): 24 accepted 0.41 m-radius cuts averaged 5.73 ms, max 7.71 ms; 24 current top-tier 0.96 m cuts averaged 17.40 ms, max 28.30 ms. Six artificial 4 m cuts averaged 195.97 ms, max 286.17 ms, rebuilding up to 216 chunks. Each radius started from reset terrain; discoveries/player were disabled. These are short terrain/cleanup/mesh/collision measurements, not whole-frame percentiles or long-excavation evidence. `TerrainVolume.TryDig` remains synchronous; discovery notification also belongs inside final edit measurements.
- Task 35 (`unity/Logs/Task35/healthy-periodic-performance.json`, `performance.json`, `allocations.json`): current 3,613,153-sample grid, changed capture normally 4–5 ms / 14,452,612 density bytes; cached capture 0.08–0.24 ms. Capture-frame allocation measured 14.475 MB versus 22 KB; initial allocation fields in the other JSON files were zero and are not allocation evidence. Checkpoints completed in 106–134 ms; continuous digging reached 10.005 s dirty at capture and about 10.14 s through durable completion. These observations do not bound slow/full disks or future saves.
- Task 35 native relaunch restored matching excavation hashes, collected identities and purchased progression after transactions, interrupted digging, rescue and normal exit. Task 16 verified bordered 1920×1080 startup on the 2560×1440 desktop, 960×540 / 1280×800 resize, and input/focus behaviour. Exact process-launch-to-Resume latency, isolated collider-cooking time, whole-frame percentiles, final-game memory and 3-hour/Continue behaviour remain **unmeasured**. Restore's 8 ms coroutine slice is an implementation threshold, not a measured load-time bound.
- Select 60 fps at the baseline tier for first-person traversal comfort. The 16 GB/SSD test configuration leaves room for persistent terrain and load/save copies; it is a planning choice, not proof that 8 GB cannot run the game. Supporting 8 GB/integrated graphics could widen access but adds constrained-memory/render testing and may require a lower quality tier; no such preset is selected. The named CPU/GPU alternatives are representative candidates, not measured performance equivalents.
- The tighter edit budget intentionally exposes current top-tier/stress costs. Lowering render resolution cannot fix synchronous CPU meshing. `58` must cost scale proposals before adoption: the present 24×24×12 m grid uses 0.125 m cells; doubling all dimensions at that spacing produces about eight times as many samples/copy bytes before mesh/collider overhead. Preserve existing saves and player-built routes when optimizing.
- Select Windows 11 to bound the qualification matrix. [Windows 10 general support ended in October 2025](https://support.microsoft.com/en-US/Windows/deployment/updates-lifecycle/windows-10-support-has-ended-on-october-14-2025); that does not prove the game cannot run on 22H2. Adding it later means a real compatibility row and driver/storage testing, with the same gameplay budgets. [Unity 6.6's engine floor](https://docs.unity3d.com/6000.6/Documentation/Manual/system-requirements.html#desktop) is broader than this game's selected support. Recheck [Windows 11 servicing](https://learn.microsoft.com/en-us/lifecycle/products/windows-11-home-and-pro) at qualification.
- Hardware access beyond this PC and Steam AppID/account/depot/branch access remain unverified. These are later validation/access gaps, not reasons to pretend minimum-hardware certification or block drafting the design. `55`/`53` consume the [platform-access contract](../../features/backlog/release-validation.md#platform-access-and-release-gate); no SDK or remote configuration was changed.
