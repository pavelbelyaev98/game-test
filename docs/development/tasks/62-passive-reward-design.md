# Task 62 - Choose the rare permanent rewards

Type: design/research; documentation only. Status: `planned`. Prerequisites: `52`, `45` and the selected real equipment systems.

Feature: [buried upgrades](../../features/backlog/buried-upgrades.md). Implementation: `36`. [Queue](../tasks.md).

## Research and proposal

- Read [persistent-investment findings](../../research/player-review-findings.md#persistent-investment), inspect actual paid equipment and the verified no-passive ending. Compare a normal run with a plausible early bonus; use the working systems rather than inventing a new receiving mechanic.
- Propose the exact 2–4 discoveries: stable reward identity, recognizable object, concrete passive benefit, starting magnitude, stacking/cap rules and how it combines with bought levels.
- Define rarity/placement within the finite population and a plain-language benefit message. Keep rewards outside sale offers, normal bag capacity and rescue losses; grant each exactly once through the save boundary.
- Include a normal and an early-lucky benefit scenario for each reward. No required collection route, new tech tree or mandatory dynamite. Exact final balance belongs to `36`/`37` playtests.
- Prepare individually reviewable asset briefs and removal boundaries; selecting an effect is not permission to create its model/audio.

## Questions to resolve with the user

Review and choose the proposed objects/effects and their intended strength. Explain interactions with purchases and any caps before implementation; do not ask for an entirely new reward list without a concrete recommendation.

## Done when

- Record the accepted reward table in the buried-upgrades feature and reference it from `36`.
- Every reward has a real receiver, measurable benefit, bounded composition and a persistence/placement contract. The verified ordinary ending remains independent of the rewards; no passive system is claimed implemented.
