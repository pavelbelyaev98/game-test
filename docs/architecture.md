# Architecture

- `unity/Assets/Runtime/Player` - input, movement, camera, battery, and player state
- `unity/Assets/Runtime/Interaction` - targeting, inventory identities, session wallet, seeded discovery placement and terrain-driven reveal/collection
- `unity/Assets/Runtime/Terrain` - finite signed density field, smooth surface-net meshes, dig adapter, permanent boundaries and derived instanced surface grass
- `unity/Assets/Runtime/UI` - HUD and menu behavior
- `unity/Assets/Runtime/Persistence` - versioned whole-world snapshots, atomic disk storage, recovery and autosave coordination
- `unity/Assets/Runtime/Validation` - disposable validation adapters, not production mechanics
- `unity/Assets/Scenes` - serialized scenes
- `unity/Assets/Editor` - editor-only tooling
- `unity/Assets/Tests` - repository-owned EditMode and PlayMode checks
- `unity/Packages/manifest.json` - direct dependency source of truth

Each scene owns one player/menu root and child camera. `FpsValidation` contains disposable control fixtures. `MainGameRoot` owns the evolving game scene: excavation, static surface/boundaries, scenery, and station/return anchors.

`DesktopInstance` reserves one Windows player before splash/scene initialization, requests the existing window on duplicate launches, and exits the duplicate without opening a profile. The process owns the kernel reservation; `WorldSaveStore` separately protects save files with its exclusive session handle. Both apply independently of Steam or development access.

`FpsHud` owns `GameUiDocument`, `GameHudView` and `GameMenuView` under `UI/Toolkit`. One runtime UIDocument/panel renders the HUD and menus from shared UXML/USS resources; `ToolkitCameraSettings` keeps persistent controls and event subscriptions. The retained EventSystem/InputSystemUIInputModule routes menu input; no Canvas HUD remains. HUD controls are cached, ignore pointer picking and hide while menus are open. Menus preserve safe focus and scroll long content independently of required actions. See [UI authoring](development/ui-authoring.md).

`FpsPlayer` owns `CameraPreferences`, `InputPreferences` and `GamePreferences`, loaded before play from separate `Preferences/camera-v1.ini`, `input-v1.ini` and `game-v1.json` files (`EditorPreferences` in the Editor). `DevicePreferencesFile` shares bounded reads/atomic writes; errors/retry stay independent of world persistence. `GamePreferences` solely owns runtime display initialization/changes, category values and confirmation; `DesktopWindow` supplies native-borderless defaults without a second startup setter; its injectable `UnityGameSettingsPlatform` applies window/pacing/audio and a disposable clone of the current URP asset, restoring globals on disposal. `FpsInput` applies validated bindings and owns toggle intent/release barriers; `InputBindingCapture` owns physical-button capture/conflict and quarantine. `ToolkitCameraSettings`, `ToolkitInputSettings`, `ToolkitDeviceSettings` and shared `ToolkitSettingsRows` retain controls; `GameMenuView` owns category tabs, standalone dialog routing and navigation. `ToolkitMenuComponents` supplies shared buttons and the dialog heading/body; all category fields use `ToolkitSettingsRows`.

The existing recharge anchor owns `SurfaceRecharge`, which samples the player's feet after movement and refills the shared battery only inside its surface bounds. `FpsPlayer` owns tunable `ReturnWarning` charge bands; `FpsHud` presents those bands and recharge context without calculating a route cost. Recharge preserves inventory, owned upgrades and excavation state.

`FpsPlayer` owns `SessionWallet`, `StationTrade` and `RescueController`. Rescue snapshots carried records and the clamped fee, validates before committing once, and leaves the collected registry untouched. The player owns landing clearance, movement/refill and menu/input restoration; successful rescue requests the same whole-world checkpoint as trades.

`WorldSaveController` on the main player owns startup selection and the local save session; its `Startup` partial gates new/load commands before world IO. It observes small state revisions/pose values, captures a consistent world on the main thread, and serializes/compresses/checksums/flushes on one background writer. Unchanged terrain reuses its immutable snapshot; changed terrain captures only a page table. Changes during writes remain dirty and queued transaction requests coalesce without storing a snapshot queue. `WorldSaveStore` locks the profile against a second writer and replaces `world.sav` atomically with `world.previous.sav` retained. Explicit new-game replacement archives the old slot under `Save/PreviousGames/<timestamp-id>/`, prepares a complete fresh checkpoint and publishes fresh recovery/primary copies before play. Incompatible/unreadable loads block play; recovery is acknowledged before continuing, with damaged originals archived.

Saves live in `Application.persistentDataPath/Save`; Editor play uses `EditorSave`, and additive validation scenes have no profile unless explicitly started with an isolated directory. Version 3 retains v1's density/seeds/discoveries/progression/player pose and v2's crouch stance, adding each find's released state; all three readers remain supported. Density pages stream through the bounded compressed payload. Loading rebuilds matching terrain render/collision meshes in frame slices, suspends find physics, and restores discoveries/exposure before play (Pause if unfocused). Find motion participates in dirty observation; saved falling finds resume from rest at their captured pose. Admin overrides are excluded; unknown old content needs an explicit migration, never fresh generation.

`SellStation` and `UpgradeStation` own offers for their current player interaction; `StationTrade` binds them to inventory/wallet revisions and owned shovel level, then prevalidates and commits without callbacks. The player rechecks station focus, distance and visibility and rejects old UI revisions. `GameMenuView` renders item rows and purchase comparisons, captures each displayed offer revision and reveals keyboard-selected rows. `StationMotion` animates only authored flap/drawer transforms. `SurfaceStationSetup` imports the approved Blender models/materials and wires their two existing anchors, independently of transaction logic.

`TerrainVolume` owns one in-memory `ExcavationGrid`, replaces the edit-mode preview with runtime chunks, and synchronously updates matching render/collision meshes after accepted organic scoops. The grid removes disconnected soil after a scoop using incremental support searches; the same accepted stroke includes its volume and expanded dirty region. `TerrainChunkMesh` reuses one sampled workspace; each fixed chunk retains a bounded density/normal-halo cache to preserve unchanged geometry and cooked collision. Permanent boundary colliders remain separate from removable soil. After mesh/collision updates, changed world bounds notify discoveries, including detached islands and resets. `ExcavationDaylight` consumes the same event to rebuild a derived, timesliced `ExcavationDaylightGrid`; an R8 volume supplies per-pixel sky occlusion to ground and an URP Lit adapter. Runtime material copies preserve authored textures/properties and are shared/restored/disposed by the daylight owner. Restored finds register through `BuriedFind.Initialize`. Lighting data is not saved and adds no excavation authority. `SurfaceGrassRenderer` derives deterministic clump patches from the original surface and current soil, consumes the same changed bounds for local support checks, and compacts visible patches into instanced batches with rooted wind and coverage-preserving geometric detail. Grass covers the whole supported original surface with seeded spacing/height variation; the retired clearing field and decorative stone renderer have no runtime ownership. Grass adds no saved state or colliders. `SunPresentationSetup` owns the camera-local skybox material, retains the clear cyan gradient and aligns its approved Blender disc with the existing light during scene authoring. It adds no runtime owner or environment-lighting override. Clouds and their drift/setup are removed.

`PagedDensity` owns writable 4,096-sample pages. `DensitySnapshot` exposes read-only samples; capture shares pages and copies the reference table. The first subsequent write to a shared page copies that page, including reset/cleanup paths. Restore shares immutable pages with the same protection. Snapshot pages and seeds are independent of the camera; `ToArray()` is reserved for explicit fixture/export copies. `SavePerformanceBuild` generates a temporary validation scene for a separate release executable; its `SavePerformanceFixture` drives MainGame with isolated profiles and reports frame/capture/IO/memory distributions. Neither fixture is attached to the normal player scene. `SurfacePerformanceBuild` likewise generates and removes a temporary scene; `SurfacePerformanceFixture` loads MainGame additively without a world-save session and measures alternating grass-on/off native CPU/GPU frame times for a fixed surface view, camera travel/turning and repeated real terrain cuts, without editing device preferences.

`DiscoveryField` owns one seeded placement/session population; each `BuriedFind` uses sampled terrain exposure plus actual visibility, then transfers its unique record to inventory. `FpsPlayer` routes input and owns `FindHandling`, which tracks one optional held world object. Eligible held/fresh collection is checked before shovel cooldown; the retired recognition timer owns no state. `FindWalkCollection` checks grounded foot contact, clear soil/obstructions and deliberate-release exclusion, then uses the same `BuriedFind` inventory commit as direct aim. `FindPickupPresentation` owns a bounded pool of nonphysical mesh copies; committed identities and save poses stay separate from the brief direct-pull effect. `FindPhysics` drives bounded physical following, per-item throwing and safe release. Holding blocks digging/collection; fresh throw consumes input intent. Checkpoints store the released world pose rather than a held/inventory duplicate; station interaction remains separate. Collected identities remain absent across sales, terrain resets, rescue and surface trips. `DiscoveryCatalog` separates stable item identity, exact shallow/total quotas and legacy-ID migration from replaceable prefab art. MainGame uses the generated `Content/StarterFinds/StarterFindCatalog.asset`; `StarterFindSetup` reads `art/starter-finds/catalog.json`, maintains stable imported assets/prefabs, centres separate visual meshes and Blender-authored collision hulls, and authors exterior samples from the visual mesh. Trial models can be replaced through the [reference/spec guide](development/replacing-find-models.md). Original `Content/Finds` prefabs remain inactive legacy/rollback assets. `DiscoveryCatalog.Entry` groups optional appearance prefabs under one item; generation chooses a seeded appearance/orientation, while stable appearance keys resolve the exact prefab during save restore. `PhotoRockSetup` reads the isolated rock catalog and reuses `StarterFindSetup` import mechanics. `FindPhysics` owns soil attachment, convex rigid-body release/settling, restore suspension and safe-pose recovery. `DiscoveryField.MotionRevision` makes moving finds visible to autosave observation; `FindSnapshot` v3 persists released state and physical pose, while v1/v2 readers remain supported. Original GUIDs and retired can/brick keys map to bottles, preserving population/history/value. `FpsPlayer` owns `ShovelState` and admin flags; `FpsHud` projects X-ray markers without changing physics/eligibility. The build flag gates admin access; purchases always use owned progression.

Update this file only when folder ownership, major system boundaries, or scene ownership changes.
