- Current scope: startup, Pause, [categorized PC settings](pc-settings.md), inventory, sell/upgrade stations, terrain-reset confirmation, developer controls and save/recovery/error screens. `122` expands settings; `123` unifies components, removes routine menu descriptions and makes display confirmations standalone; preserve concise loss/error information.

## Behavior that survives restyling

- Preserve the [FPS input barriers](fps-controls.md) and [camera comfort contract](camera-comfort.md). Escape has one owner. Display, Graphics, Audio, Controls and Accessibility are sibling tabs (`122`); Back returns to originating startup/Pause and focuses Settings. Switching tabs flushes changes; ordinary edits retain focus. Rebinding and display confirmation disable category changes. Every setting takes effect on change; no Apply buttons. Mode/resolution opens a standalone Keep/Revert dialog without tabs; Escape first closes a dropdown or reverts a display preview, then returns to Settings. Matching compact Back/Reset buttons sit together at the bottom left. Pause has no save timestamp; dialog/shop actions are compact and right-aligned.
- Inventory inspection never sells. Stations show named rows, values, current/next equipment comparisons and explicit purchases; stale offers cannot mutate state. Confirmations share one compact frame, a single title, short loss information and standard buttons. Safe focus never becomes a second primary fill.
- Startup order: Continue, New Game, Settings, Quit. Continue uses the same neutral style as every startup action. It loads the existing single slot and is the internal keyboard starting point when available, with focus painted only after keyboard navigation; otherwise it is disabled with an explanation and New Game is focused. Pause offers Resume, Settings, Save and quit, with an identically styled Developer admin button only in development builds. Browsing/settings/quit leave the world untouched. New Game confirms replacement when a checkpoint exists, focuses Cancel first, retains a recovery archive and starts fresh only after its first checkpoint succeeds. Continue never silently generates a world on failure.
- Windows builds allow one concurrent game instance, independently of Steam and development/release mode. Keep exclusive save ownership as a safeguard; contention explains that the save is already open and allows Retry, Back to menu and Quit. OS exception details and personal filesystem paths belong in diagnostic logs, not menu text.
- Selected in [124](../../development/tasks/124-monochrome-control-states.md): release save-write failures log diagnostics and quit silently, preserving the last completed checkpoint. Development retains the write-error/Retry/unsaved-exit diagnostics. Open save folder is removed from all menus; loading/recovery failures retain Retry/Back/Quit as applicable. Camera preference failures stay local and retryable. Starting/loading enters gameplay only when ready and focused; focus loss leaves Pause visible. Ordinary menu navigation cannot create checkpoints or erase excavation.
- Menus adapt to the supported window sizes and scroll long content while keeping necessary actions accessible. Disabled actions explain their state; mouse/keyboard focus remains visible. Hide the gameplay HUD while a menu is open; inventory/trading screens show the relevant carried counts and credits within their own layout. Restore the existing quiet HUD on Resume.
