The table retains the original idea assessment. The user has now selected bottle-only physical release and larger/60%-exposed pickups in `110`; other optional mechanics remain proposals. The user clarified that **enjoyable vertical flight and dull horizontal return travel refer to Meltopia, not this game**. Treat that as a comparator observation to investigate here; no current-game movement failure or successful fix is established. Current input and free recharge stay implemented baselines while the alternatives below are designed.

## Suggested order and the feel to preserve

Start with current-build observations in `100`/`101`; use them to test whether Meltopia's travel problem applies here before selecting a remedy in `99`. Develop special-find recognition/interaction and selective movement through `96`/`97`, then use `40` for the actual named objects, chest rewards and rare sound sources. Review fuel policy in `98` before coupling it to a teleporter price or rescue rebalance. Dynamite remains a keep/defer/omit decision in `71`.

The game should create curiosity, growing physical capability and occasional absurd surprises. Peaceful excavation is one part of that, not a requirement that every moment be passive or cozy. A collectible can justify itself through recognition, humor and the personal display without providing a mechanical upgrade. A new cost should create an understandable choice; a convenience should remove a demonstrated dull action while preserving enjoyable ones.

## Evidence and limits

The [634-review audit](steam-review-audit/report.md) supports testing whole-trip purchase value, recognizable rewards, finite-income recovery and voluntary hole shaping. A [positive Hole review](https://steamcommunity.com/id/Synikx/recommended/3244220/) specifically reports bouncing dynamite and repetitive sound while enjoying stronger digging and reshaping the hole; it supports testing control and fatigue, not adding general object physics by itself. The proposed solutions above are design judgments, not proven effects.

Inspected current behavior: [BuriedFind](../../unity/Assets/Runtime/Interaction/BuriedFind.cs) collects through the held-primary path and already saves pose/identity; `FindPhysics` now adds the selected bottle attachment/release/rest policy through `110`. [SurfaceRecharge](../../unity/Assets/Runtime/Player/SurfaceRecharge.cs) refills automatically without a wallet transaction. [FpsPlayer](../../unity/Assets/Runtime/Player/FpsPlayer.cs) uses the same planar walking/sprint speed in flight; current thrust changes vertical motion. These are scoped implementation observations, not proof that an engine change or a new mechanic is necessary.

Use the [playtest list](../development/playtesting.md) to mark actual feelings. Missing production art/audio or an unimplemented proposed mechanic is **NOT READY**, not a failed player verdict. Only a reviewed design decision should replace the relevant concept/feature rule or create its implementation task.
